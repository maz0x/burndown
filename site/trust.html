What Burndown reads, what it contacts, and how to check

An app that watches your AI usage should expect suspicion, so this page is the complete inventory: every file it reads, every host it can contact in each mode, how update downloads are verified, and how to confirm all of it yourself rather than take my word.

Every file it reads

PathWhat it takes from itWhen
~/.claude/projects/**/*.jsonl Claude Code's session logs. Burndown extracts token counts, timestamps, model names, and chat titles for the gauges, charts, and attribution. The logs also contain your conversation text; Burndown stores none of it, and nothing extracted from these files ever leaves this Mac in any mode. Always (this is estimate mode and attribution)
~/.claude.json Only the oauthAccount block: your plan tier for the plan label, and the account email and organization name for display. Nothing else in the file is read. Always, for the plan label
~/.claude/.credentials.json, or Claude Code's Keychain item Claude Code's own sign-in token, used only to call Anthropic's usage endpoint if you opt in to live mode with the existing sign-in. When live mode is off, Burndown checks only that the item exists; it never reads the secret. Live mode only, opt-in

Burndown's own files (settings, chart data, chat-title aliases) are written to its own config directory with mode 600 inside a mode 700 directory, private from the instant each file exists (Sources/PrivateFile.swift).

Every host it can contact

ModeHostsWhat is sent
Estimate mode (the default) None. Zero network connections. Nothing.
Live mode (opt-in) api.anthropic.com Your own OAuth token, to read the same usage numbers behind claude.ai's usage page. Nothing else is transmitted. The endpoint is undocumented and itself rate limited, so during heavy bursts the live gauges can lag; Burndown labels stale or estimated values instead of pretending.
Update check api.github.com, and github.com / *.githubusercontent.com for the download itself A standard HTTP request for the latest release, which necessarily reveals your IP address and app version to GitHub, the same as any update check. You can set the cadence, including Manual, in Settings. The allowlist in Sources/Updater.swift refuses every other domain.

There is no telemetry, no analytics SDK, no crash reporter, and no server of mine anywhere in the app. So the claim is not "nothing ever leaves your machine"; it is narrower and checkable: in estimate mode nothing leaves, and in every mode the only possible destinations are the three hosts above.

How updates are verified

The updater refuses to install any release that does not publish a checksum, and verifies the downloaded zip's SHA-256 against the published value before swapping anything. Honest limit: the checksum is published alongside the release on GitHub, so this protects against corrupted or tampered downloads, not against a full compromise of the GitHub account itself. A signed update manifest is on the roadmap; until then, the strongest guarantee available is building from source, which takes one command and about a minute.

One honest scope note

The limit gauges are account-wide: claude.ai chats and your other devices spend the same limits. Burndown's per-chat attribution comes from the Claude Code logs on this Mac, so it explains your local share of the spending, not necessarily all of it. The app says this in place rather than letting the numbers quietly disagree.

Terms-of-service posture

Burndown is a read-only monitor: it never runs inference with your token and never spends your subscription; it only asks how much you have used. The sourced, plain-English analysis of where that stands lives in docs/TOS_NOTES.md, including what happens if Anthropic closes the endpoint: the app degrades to estimate mode and keeps working.

Verify it yourself

The fastest way to trust this app is to not trust me:

  • Read the code that touches anything sensitive. Four files cover all of it: UsageEngine.swift (log parsing and credential reading), APIAccount.swift (the opt-in PKCE sign-in), Updater.swift (the network allowlist and checksum verification), and PrivateFile.swift (how its own files are kept private).
  • Watch the network. Run the app in estimate mode with Little Snitch, LuLu, or plain nettop -p Burndown: you will see no connections. Turn on live mode and you will see exactly one host; trigger an update check and you will see GitHub. That is the whole list.
  • Make the binary question disappear. The release zip is a convenience, not the trust anchor: the app builds from source with one script, no Xcode project and no dependencies, so you can compile exactly what you read.
git clone https://github.com/maz0x/burndown && cd burndown
./build.sh
open Burndown.app
